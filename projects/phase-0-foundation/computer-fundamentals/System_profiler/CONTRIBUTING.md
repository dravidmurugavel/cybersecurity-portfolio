# Contributing Guide

Thank you for your interest in contributing to the **System Profiler** project.

Contributions that improve code quality, documentation, portability, security, and usability are welcome.

---

# Ways to Contribute

You can contribute by:

* Reporting bugs
* Suggesting new features
* Improving documentation
* Optimizing Bash scripts
* Enhancing portability across Linux distributions
* Improving report formatting
* Adding new system profiling modules
* Improving security checks
* Refactoring existing code

---

# Development Guidelines

Please follow these guidelines when contributing:

* Keep functions modular and focused on a single responsibility.
* Use descriptive variable and function names.
* Maintain consistent formatting and indentation.
* Prefer standard Linux utilities over external dependencies.
* Preserve compatibility with common Linux distributions whenever possible.
* Add comments where the purpose of the code is not immediately obvious.

---

# Code Style

The project follows these conventions:

* Language: Bash
* Indentation: 4 spaces
* Function names: lowercase with underscores
* Variable names: UPPERCASE for constants, lowercase for local variables
* Use meaningful comments for modules and complex logic
* Validate user input where appropriate

Before submitting changes, verify that:

* The script executes without errors.
* Existing functionality continues to work.
* New features do not break report generation.
* The code passes `shellcheck` with no significant warnings.

---

# Reporting Issues

When reporting a bug, please include:

* Linux distribution and version
* Bash version
* Steps to reproduce the issue
* Expected behavior
* Actual behavior
* Error messages (if any)
* Relevant screenshots or report excerpts

---

# Feature Requests

Feature requests should include:

* A clear description of the proposed feature
* The problem it solves
* Why it would improve the project
* Any implementation considerations

---

# Pull Requests

Before submitting a pull request:

* Create a dedicated branch.
* Keep changes focused on a single improvement.
* Update documentation if necessary.
* Ensure the project remains functional.
* Include a clear description of your changes.

---

# Code of Conduct

Please be respectful, constructive, and professional when participating in discussions or submitting contributions.

This project is intended to support learning, collaboration, and the sharing of defensive cybersecurity knowledge.

---

# Security

This project is designed for **system administration**, **defensive security**, and **educational purposes**.

Please do not submit features intended to facilitate unauthorized access, malicious activity, or offensive use.

---

Thank you for helping improve **System Profiler**.
