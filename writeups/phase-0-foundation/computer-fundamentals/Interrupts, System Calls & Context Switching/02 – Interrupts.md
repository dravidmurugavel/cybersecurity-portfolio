# Overview

An **interrupt** is a signal that temporarily pauses the CPU's current execution so it can respond to an important event. After handling the event, the CPU restores its previous state and resumes the interrupted task.

Interrupts are fundamental to modern operating systems because they allow hardware and software to efficiently communicate with the CPU. Instead of constantly checking every hardware device for new events, the CPU responds only when an interrupt occurs, significantly improving system performance.

Understanding interrupts provides the foundation for learning system calls, process scheduling, device drivers, malware analysis, and operating system internals.

---

# Why This Matters in Cybersecurity

Every interaction between hardware and the operating system depends on interrupts.

Keyboard input, network communication, disk operations, timers, and USB devices all rely on interrupts to notify the CPU when attention is required.

Security professionals frequently encounter interrupt-driven activity while analyzing malware, investigating suspicious drivers, monitoring system behavior, and understanding how operating systems respond to external events.

# Core Concepts

## What is an Interrupt?

An **interrupt** is a signal that temporarily stops the CPU's current execution, allowing it to process an event that requires immediate attention.

The CPU follows a simple sequence:

1. Pause the current task.
2. Save the current execution state.
3. Execute the appropriate interrupt handler.
4. Restore the saved state.
5. Resume the interrupted task.

This process typically completes within a fraction of a millisecond.

---

## Why Are Interrupts Needed?

Without interrupts, the CPU would constantly check every hardware device to determine whether it required attention.

This process is known as **polling**.

Example:

```text id="5h4s2q"
Keyboard?
No.

Mouse?
No.

Disk?
No.

Network?
No.
```

Continuous polling wastes valuable CPU time.

Interrupts solve this problem by allowing hardware devices to notify the CPU **only when an event occurs**, making the operating system significantly more efficient.

---

## Hardware Interrupts

A **hardware interrupt** is generated by a physical hardware device.

Common examples include:

* Keyboard key press
* Mouse movement
* Disk read or write completion
* Network packet arrival
* USB device insertion

Example:

When a user presses a key on the keyboard, the keyboard immediately sends an interrupt signal to the CPU. The CPU temporarily pauses its current task, processes the keyboard event, and then resumes the interrupted program.

---

## Software Interrupts

A **software interrupt** is generated by software rather than physical hardware.

Software interrupts are commonly used to:

* Request operating system services.
* Signal exceptional conditions.
* Transition execution into the operating system kernel.

Historically, software interrupts were frequently used to invoke system calls. Modern operating systems often use more efficient processor instructions, but the underlying concept remains the same: software requests services from the operating system kernel.

---

## Interrupt Handling

When an interrupt occurs, the CPU does not simply abandon its current task.

Instead, it carefully preserves the execution state before handling the event.

The process follows this sequence:

```text id="0jk2cm"
Running Program
       │
       ▼
Interrupt Occurs
       │
       ▼
CPU Saves Current State
       │
       ▼
Interrupt Handler Executes
       │
       ▼
CPU Restores Previous State
       │
       ▼
Program Continues
```

This mechanism allows the operating system to remain responsive while ensuring that applications continue executing correctly after the interrupt has been processed.

# Hands-on Lab

## Linux

Display interrupt statistics:

```bash id="w5c8pa"
cat /proc/interrupts
```

Observe interrupt activity in real time:

```bash id="6l2kxf"
watch -n 1 cat /proc/interrupts
```

Move the mouse, press keyboard keys, or generate network traffic and observe interrupt counters increasing.

---

## Windows

Open **Resource Monitor (`resmon`)**.

Observe:

* CPU activity
* Disk activity
* Network activity

These hardware operations are coordinated through interrupt-driven communication between devices and the operating system.

# Real-World Security Example

A network intrusion detection system monitors incoming network traffic for malicious activity.

Whenever a network packet arrives, the network interface card generates a **hardware interrupt**, notifying the CPU that new data is available. The operating system processes the packet before passing it to applications or security software for inspection.

Without interrupts, the CPU would waste significant resources continuously polling the network interface for new packets, reducing overall system efficiency.

This illustrates why interrupt-driven processing is essential for both operating system performance and real-time security monitoring.
